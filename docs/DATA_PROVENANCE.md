# Demo data and provenance

## Policy

VELA uses controlled synthetic data for the judged journey. The repository must not contain real insurance cards, referrals, medical records, member identifiers, credentials, or private audit exports.

Every material value presented by the application should be identifiable as one of four categories:

1. A source fact copied or parsed from a controlled input.
2. A model proposed fact that is not authoritative until validated or confirmed.
3. A deterministic value calculated from source backed inputs.
4. A natural language explanation grounded in authoritative engine output.

## Data inventory

| Data class | Repository location | Origin | Use | Authority and limitations |

| Provider catalog | `src/abyss/catalogs.py` and scenario fixture | Manually authored synthetic fixture | Provider, network, facility, and constraint evaluation | Controlled values; not a live provider directory |

## Transformations

### Documents and voice

The onboarding path converts voice or document content into candidate facts. Candidate facts are schema validated, assigned provenance and confidence, and retained as inferred or source backed until confirmed. Missing fields remain missing. VELA does not use a model to fill absent insurance benefits.

### Eligibility and cost

The deterministic engine combines the controlled plan and provider records with verified journey facts. It evaluates hard constraints, calculates visible annual cost components, excludes infeasible paths from recommendation, and preserves rejection reasons.

### Explanations

Nemotron receives a compact authoritative snapshot containing fact references and path evaluations. Its output is an explanation, not a new eligibility, cost, network, or consent decision.

## Reproducibility

The deterministic fixture and tests require no external dataset download and no API credential:

```bash
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

The judged demo should use the same synthetic fixture for every rehearsal and recording. If a live catalog, public dataset, or external adapter is added, record its source URL, retrieval timestamp, parser version, fields used, and fallback behavior here before submission.

## Known gaps

- The fixture does not represent every Washington plan, benefit design, or eligibility rule.
- Provider and network records are not continuously synchronized with payer directories.
- Procedure normalization covers the demonstrated MRI case rather than the full coding system.
- Synthetic documents do not capture every real world layout or scan quality problem.
- Estimated costs are illustrative and are not guarantees of benefits or patient responsibility.
